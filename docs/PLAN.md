- 게임 본체는 C++로 작성해 Wasm으로 실행한다. HTML/JavaScript는 브라우저 API 연결과 서버 전송을 담당한다.
- 로우폴리 맵 하나, WASD 이동, 마우스 시점·조준, 사격·재장전, 체력·사망·부활, 최대 4명 방 기반 멀티플레이.
- 인터넷 공개 배포, 원격 저장소 생성·push, 방화벽 변경은 이번 승인에 포함되지 않는다.

## 첫 구현의 기본값
다음은 v0.1 첫 구현의 기본값이며 배틀비트 규칙을 복제하지 않는다. 승인된 후속 확장과 현재 적용 여부는 아래 및 `docs/ACTIONS.md`에서 구분한다.
- 4인 자유 교전. 한 명도 바로 맵을 둘러볼 수 있다. 봇·승패·매칭·팀 구성은 없다.
- 체력 100, 피해 25, 탄창 24발, 사격 간격 0.12초, 재장전 1.5초, 부활 2.5초, 부활 보호 1.5초. 사격 시 보호 해제.
- 이동 5m/s, Shift 달리기 7m/s, 점프·차량·지형 파괴 없음. 오른쪽 마우스 조준 시 시야각 축소.
- C++ 공통 시뮬레이션을 서버(Node.js의 Wasm)와 브라우저가 공유한다. 서버가 위치·명중·피해·탄약·킬을 결정한다.
- 클라이언트는 같은 충돌 함수로 내 이동을 예측하고 서버 위치로 보정한다. 마우스 조준은 서버의 오래된 yaw로 덮어쓰지 않는다. 상대는 보간한다.
- 렌더링: WebGPU 우선, WebGPU가 없거나 보안 컨텍스트가 아닌 LAN HTTP에서는 WebGL2로 대체한다. UI에 실제 사용 중인 API를 표시한다.
- CPU 게임 로직·맵·카메라·모델 배치는 C++. GPU API·WebSocket·DOM·오디오 연결만 작은 JavaScript 어댑터가 담당한다. Three.js나 Unity를 쓰지 않는다.
- 서버 기본값은 `127.0.0.1:8088`. 방·이름·전적은 메모리에만 있으며 서버 종료 시 사라진다.

## 작업 순서
후속 승인: 점프·앉기 → 보조무장 권총 → 일반 폭발형 수류탄을 구현한다. Space/C/1·2/G 기본키를 사용하며, 행동·충돌·자원·전송 계약과 계획된 검증은 [ACTIONS.md](ACTIONS.md)에 있다. 공통 C++ 판정과 전송, 실제 브라우저 조작을 연결했다. 최종 회귀·검토 결과와 미검증 범위는 `docs/VERIFICATION.md`에서 별도로 확인한다.

1. 설계 계약·Git·Emscripten 준비.
2. 공통 C++ 시뮬레이션의 세로 단위 TDD: 이동 → 충돌 → 사격 → 재장전 → 사망·부활 → 입력 경계.
3. 브라우저 C++ 클라이언트와 WebGPU/WebGL2 어댑터.
4. 방·WebSocket 서버와 C++ 모듈 연결.
5. 단위·서버·실제 소켓·독립 브라우저 컨텍스트·시각 검증과 리뷰.

## 완료 기준
- C++를 실제로 컴파일한 `.wasm`이 브라우저에서 로드되고 맵이 표시된다.
- 실제 클릭으로 포인터 잠금, WASD 이동, 마우스 조준, 탄약 감소·재장전, Esc 해제를 확인한다.
- 독립된 4개 클라이언트가 같은 방의 위치·체력·사망·부활·킬을 확인한다. 테스트 참가자는 자동화 클라이언트임을 표시한다.
- 5번째 입장, 잘못된 입력, 벽 관통 사격, 사격 속도·이동 속도 제한, 연결 해제·빈 방 정리를 검사한다.
- 느린 수신자가 공통 시뮬레이션을 막지 않는 회귀 테스트를 유지한다.
- 1440/768/375 폭에서 로비·메뉴가 잘리지 않는다. 모바일 터치 플레이는 범위 밖임을 안내한다.
- 실제 별도 물리 기기의 LAN 접속은 이번 동일 PC 검증과 구별해 미검증으로 남긴다.
- 실행 안내, 실제 명령·종료 코드·코드 지문·캡처, 제한 사항을 남긴다. 준비 상태를 실행 성공으로 표현하지 않는다.
